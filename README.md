# ORcode — Holy Open Relay (HOR-loop)

> 🔄 **HOR-loop = Holy Open Relay** — 多模型协作框架

## 🎯 项目简介

**ORcode** 是一款运行在终端里的命令行 AI 智能体工具，核心采用 **HOR-loop (Holy Open Relay)** 多模型工作流：把复杂任务交给一棵「岗位树」——流程层（Director / Planner / Workers / Verifier）分工协作，其下再挂研究员、程序员、测试员、批评家、美术指导、视觉设计师等 15 个职能岗随需调度（Workers 的子智能体可并行），而不是单靠一个模型。

- 输入 `orcode` 进入**交互式 TUI 终端界面**（暗色主题、鼠标可操作、实时工作树）；
- 或用 `orcode run "指令"` **直接在命令行跑一次任务**；
- 支持任意 OpenAI 兼容协议（DeepSeek / Moonshot / 本地 vLLM 等），也支持 Anthropic / Google / Ollama。

### ✨ 主要特性

- **两种使用模式**：普通文字 = 单模型直接对话；`/hor-loop` = 多模型全流程协作
- **五步添加模型**：供应商 → Base URL → API Key → 模型 ID → 显示名称，不预置任何假模型
- **`/models` 模型选择面板**：按供应商分组，键盘 / 鼠标悬停选择，支持搜索过滤
- **实时工作树**：右侧岗位状态随执行动态更新，当前执行岗位高亮；**岗位树带子分支**——流程层（指挥/规划/执行/检验）下挂 15 个职能岗（产品经理/协调员/架构师/美术指导/研究员/数据师/程序员/测试员/安全审计/批评家/润色官/翻译官/视觉设计师/图像分析师/摘要员），支持折叠/滚动；Workers 的子智能体并行执行；**点击岗位行 = 在顶部新标签页打开该模型的子会话窗口（只读，不可对话）**
- **对话历史翻看**：每轮对话有分割线，`PgUp`/`PgDn`/滚轮翻看，滚动条指示位置
- **模型上下文与记忆**：调用时自动注入工作区/最近对话/相关记忆；模型可主动记忆（`<<<MEMORY>>>` 块），也可 `/remember` 手动记
- **模型文件工具**：模型可通过 `<<<READ>>>`/`<<<LIST>>>` 工具块真实读取工作区内文件，`<<<SEARCH>>>` **自动触发**联网搜索（无需 /search），结果回传继续任务；权限系统实时把关
- **自适应换行与会话存档**：历史日志按面板宽度自动折行不丢内容；`/archive` 手动存档、关会话自动存档、`/archives` 随时翻找
- **工作区权限系统**：工作区内完整权限，跨工作区访问需用户批准（Y 记住 / E 仅本次 / N 拒绝）
- **设置面板**：可视化调整 workers 数量、验证轮数、读取上限，鼠标点击 `<` `>` 即调；岗位模型、初始模型、添加模型全部支持点击操作
- **SQLite 持久化**：自动记录每轮会话与消息（Node 22+ 内置 `node:sqlite`，不可用时降级内存）
- **零重型依赖**：核心逻辑纯 Node.js 内置模块，ANSI TUI 自绘，无需 ink 等框架

## 🚀 快速开始

### 环境要求

- **Node.js ≥ 22.0.0**（SQLite 持久化依赖 Node 22+ 内置的 `node:sqlite`）
- 一个可用的模型 API Key（DeepSeek / OpenAI / 本地 Ollama 等均可）

### 安装

```bash
# 1. 克隆仓库
git clone https://github.com/05ca2/ORcode.git
cd ORcode

# 2. （可选）设为全局命令，之后可在任意目录使用 `orcode`
npm link
# 或直接用 node 运行（无需安装）：node orcode.cjs

# 3. 查看版本
orcode --version
```

> 提示：`npm link` 会把 `orcode` 命令软链到全局；若不想污染全局，直接 `node orcode.cjs` 也能用。

### 初始化（引导添加第一个真实模型）

```bash
orcode init
```

首次初始化引导你添加自己的模型（五步，**不预置任何假模型**）：

```
📦 首次使用 — 请添加你的第一个模型 (之后可在设置中继续添加)
   [直接回车可跳过, 稍后在 TUI 设置中添加]

  步骤 1/5 · 供应商名称 (如 openai / deepseek / ollama): deepseek
  步骤 2/5 · Base URL (如 https://api.deepseek.com/v1): https://api.deepseek.com/v1
  步骤 3/5 · API Key (可留空): sk-xxxxxxxx
  步骤 4/5 · 模型 ID (如 deepseek-chat): deepseek-chat
  步骤 5/5 · 显示名称 (如 DeepSeek V3): DeepSeek V3

✅ 初始模型已设为: DeepSeek V3 (deepseek)
```

添加的模型会成为所有岗位的初始模型，状态栏左侧也会显示它。**未配置模型时，单模型调用和 `/hor-loop` 都会提示先添加模型**。

## 🔄 HOR-loop 工作流

`/hor-loop` 启动后输入任务，四个流程岗位依次协作：

```
/hor-loop 输入任务
    ↓
👨‍💼 Director 指挥     接收指令，协调全局
    ↓
🧠 Planner  规划      分析需求，制定执行步骤
    ↓
💻 Workers × N       并行执行（数量可配置 1-8）
    ↓
👀 Verifier × M      核查结果，驱动修复（轮数可配置 1-5）
    ↓
🎯 Director 指挥     整合输出（荧光粉高亮）
```

**岗位树**：右栏工作树在这 4 个流程岗之下还挂 15 个职能岗（产品经理 / 协调员 / 架构师 / 美术指导 / 研究员 / 数据师 / 程序员 / 测试员 / 安全审计 / 批评家 / 润色官 / 翻译官 / 视觉设计师 / 图像分析师 / 摘要员），共 **19 个岗位**，每个都可单独分配模型。

**点击工作树任意岗位行 = 打开该模型的子会话窗口**（新标签页、只读），详见 [岗位树与子会话窗口](#-岗位树与子会话窗口只读)。

## ⚙️ 配置

配置文件位于 `~/.orcode/config.json`（由 `orcode init` 和设置面板自动生成）：

```json
{
  "workers": 2,
  "verifyRounds": 1,
  "defaultModel": { "name": "DeepSeek V3", "provider": "deepseek" },
  "models": [
    {
      "name": "DeepSeek V3",
      "provider": "deepseek",
      "baseUrl": "https://api.deepseek.com/v1",
      "modelId": "deepseek-chat"
    }
  ],
  "positions": {
    "director": { "name": "DeepSeek V3", "provider": "deepseek", "baseUrl": "...", "modelId": "deepseek-chat" },
    "planner":  { "...": "同上" },
    "worker":   { "...": "同上" },
    "verifier": { "...": "同上" },
    "draft":    { "...": "同上" }
  },
  "apiKeys": {
    "deepseek": "sk-..."
  },
  "pathPermissions": {
    "/home/user/shared-docs": "read"
  }
}
```

- `workers`：并行 worker 模型数量
- `verifyRounds`：verifier 验证轮数
- `defaultModel`：单模型调用使用的初始模型
- `models`：已添加的模型列表（name=显示名，provider=供应商，baseUrl，modelId=实际模型 ID）
- `positions`：每个岗位使用的模型（可重复）
- `apiKeys`：按供应商名存储的 API Key
- `pathPermissions`：智能体获批的工作区外路径权限（`full` 完整 / `read` 只读），在权限申请面板按 `Y` 时自动写入

### 支持的供应商

| provider | 协议 |
|----------|------|
| `openai` | OpenAI `/chat/completions` |
| `anthropic` / `claude` | Anthropic `/messages` |
| `google` / `gemini` | Gemini `generateContent` |
| `ollama` | 本地 Ollama（无需 Key） |
| 其他任意名称 | 默认走 **OpenAI 兼容协议**（配 baseUrl 即可，如 DeepSeek / Moonshot / 本地 vLLM） |

> 未配置 API Key 的供应商在调用时会明确报错提示，不会静默使用占位响应——请先通过 `orcode init` 或设置面板 `[+ 添加模型]` 添加真实模型。

### 📜 对话历史翻看

- **每轮对话之间自动有分割线**，你的输入会以 `▸ 你: ...`（高亮色）记入历史，方便回顾完整对话

- 历史按会话独立保存，切换会话标签后各自的位置仍然保留

- `/archive`（或 `/save`）：把当前会话完整导出为 Markdown 存档到工作区（含时间/工作区/模型等头信息，分割线转 `---`）
- **自动存档**：关闭会话标签（`Ctrl+W` / `/close`）时，有对话内容的会话会先自动落盘再关闭
- `/archives`：列出当前工作区最新 10 份存档（大小 + 时间）

右栏工作树是一棵两层岗位树——**流程层**（HOR-loop 主流程）+ **职能层**（随需调度的专业岗）：

```
│ ├─   ○ 研究员 Researcher  -

│ ├─   ○ 安全审计 Auditor  -

│ ├─   ○ 图像分析师 Vision Analyst  -
  └─   ○ 摘要员 Summarizer  -
  ○ 检验 Verifier  -
```

- **树操作**：点行尾 `▸`/`▾` 折叠/展开子分支；内容超高时滚轮滚动；`tab` 切换岗位时自动跟随焦点；长标签按面板宽度自动截断
- **子智能体执行**（HOR-loop 运行时）：
  - **Director / Planner 的子智能体顺序执行**（产品经理→协调员；架构师→美术指导），一个个来
  - **Workers 的 11 个子智能体并行执行**（`Promise.all` 同时发起，各自独立走 思考→执行→完成，树上一排 `●` 同时推进）——**并行只限 Workers**，其他父节点的子岗不并行

- **窗口内容**：该模型的子会话记录（HOR-loop 中各岗位的活动自动归档；单模型调用的问答按「模型属于哪个岗」自动归位）+ 最近思考

- 19 个岗位均可在设置面板分配独立模型（点岗位行选中、再点循环换模型，`Esc` 保存写入 `config.json`）

### 🧠 模型上下文与记忆系统

模型每次被调用时，会自动收到三部分上下文（随指令一起发送，模型可翻阅、可调用）：

| 部分 | 内容 |
|------|------|
| `[环境]` | 当前工作区路径与权限说明 |
| `[最近对话]` | 最近 3 轮你的输入（`▸ 你: ...`） |
| `[你的记忆]` | 与当前指令关键词相关的长期记忆（最多 5 条） |

**记忆的两种写入方式**：

1. **模型主动记忆** — 模型在回复末尾嵌入记忆块，TUI 自动提取并保存（界面显示 `🧠 已记住: ...`）：
   ```
   <<<MEMORY
   {"content":"用户喜欢简洁的回答","tags":["偏好"]}
   MEMORY>>>
   ```
2. **手动记忆** — `/remember 用户是九年级学生`，可带任意文本

**管理命令**：

| 命令 | 功能 |
|------|------|
| `/remember <事实>` | 存入长期记忆 |
| `/memory` | 查看记忆库（最近 10 条，含 ID/来源） |
| `/forget <ID 或 关键词>` | 删除匹配的记忆 |
| `/context` | 预览下一次调用将发送的完整上下文 |

记忆持久化在 `~/.orcode/memory.json`（最多保留 200 条，含 id/content/tags/source/createdAt），跨会话、跨会话标签生效。

### 📂 模型文件工具（真实读取）与联网搜索

模型不再只能“聊天”——它可以通过工具块**真实读取你电脑上的文件、联网搜索资料**，权限系统实时把关：

| 工具块 | 作用 |
|--------|------|
| `<<<READ {"path":"文件路径","reason":"原因"} READ>>>` | 读取文件（默认 ≤100MB、单次 ≤20000 字符，均可调） |
| `<<<LIST {"path":"目录路径","reason":"原因"} LIST>>>` | 列目录（最多 100 项，标注 `[目录]`/`[文件]`） |
| `<<<SEARCH {"query":"搜索词","reason":"原因"} SEARCH>>>` | **联网搜索**（DuckDuckGo，返回标题/链接/摘要，最多 8 条） |

**搜索全自动触发**：无需用户要求，也无需 `/search` 命令——遇到时效性信息（新闻/价格/版本/天气等）、知识可能过时或需要外部资料验证时，模型会**主动发起搜索**再作答。`/search` 仍保留，供手动直接查询。

**工作流程**：模型回复中嵌入工具块 → TUI 解析并执行（`📖 已读取文件` / `📂 已列出目录` / `🌐 已搜索` 日志）→ 结果放入 `[文件结果]` 回传给模型 → 模型基于内容继续（最多 5 轮工具循环）。

**读取上限（可配置）**：

| 上限 | 默认值 | 调整方式 |
|------|--------|----------|
| 文件大小 | **100MB** | 设置面板点击 `<` / `>`（1-500MB），或 `/readlimit <MB>` |
| 单次字符数 | **20000** | 设置面板点击 `<` / `>`（2k-200k） |

持久化在 `config.json` 的 `maxFileReadSize` / `maxFileReadChars`，旧配置自动补齐。

**大文件与二进制保护**：超过字符上限时只读取文件前段（按 UTF-8 最坏 4 字节/字符估算，避免把几百 MB 整体载入内存）并截断到上限；前 1024 字节含 NUL 字节的文件判定为**二进制**（PPT/PDF/图片/压缩包等），直接跳过不喂入乱码。

**权限联动**（这就是权限系统真正生效的地方）：
- 工作区内的文件：🔓 直接读取，无需申请
- 工作区外的文件：弹出权限申请面板（Y 记住 / E 仅本次 / N 拒绝）；拒绝则模型收到失败提示并转告用户
- 相对路径基于工作区根目录解析，也支持绝对路径和 `~`

路径规则：空路径/不存在/目录当文件读/超过大小上限都会返回明确错误给模型，模型可自行修正重试。

### 🔐 工作区权限系统

智能体对文件系统的访问遵循**最小权限原则**：

- **工作区内**（当前会话的工作区目录，含子目录）：🔓 自动拥有**完整权限**（读/写/执行），无需申请
- **工作区外**：🔒 默认**拒绝**，任何访问都会弹出**权限申请面板**，由你决定

权限申请面板操作：

| 按键 | 行为 |
|------|------|
| `Y` | 同意授权，并**写入配置**（`~/.orcode/config.json` 的 `pathPermissions`，跨会话生效） |
| `E` | **仅本次授权**（当前任务有效，不写入配置） |
| `N` / `Esc` | 拒绝本次访问 |
| 点击面板外 | 等同拒绝 |

其他说明：

- 授权粒度为**单个绝对路径**；已授权的路径再次访问会直接放行，不再弹面板
- 已获 `read`（只读）的路径请求写入/执行时，会再次弹出面板申请**权限升级**
- 左上角显示 `🔓 工作区内: 完整权限 · 🔑 已授权区外路径: N`，状态栏有权限徽章
- 输入 `/perm` 随时查看当前权限概览（工作区、已授权/拒绝的路径列表）
- 每个会话的工作区可不同（`/cd` 切换），权限按**路径**记录，切会话后仍生效

### 📋 智能体问卷 (Agent Questionnaire)

当模型对任务有不确定之处时，可以在回复中嵌入一份问卷，TUI 会弹出交互面板让用户作答；答案会回灌给模型继续完成任务（最多 5 轮澄清）。

- 单模型调用（`runSingleModel`）与 HOR-loop 各岗位执行均支持。
- 每个问题可为**单选**（`multi: false`）或**多选**（`multi: true`）。
- 面板操作：`↑↓` 切换问题/选项 · `空格` 选择或勾选（多选可多项）· `enter` 提交 · `esc` 跳过 · 鼠标悬停移动光标、点击选项即选。
- 想先体验：输入 `/ask` 回车，即可看到一份示例问卷。

模型触发格式（回复末尾嵌入，选项需具体）：

```
<<<QUESTIONNAIRE
{"title":"确认信息","questions":[
  {"id":"q1","prompt":"目标语言?","multi":false,"options":["中文","English"]},
  {"id":"q2","prompt":"重点关注?","multi":true,"options":["性能","可读性","安全性"]}
]}
QUESTIONNAIRE>>>
```

### 设置面板

**打开方式**：点击右下角 ⚙ 齿轮 / `Ctrl+O` / `/settings`

**面板内全部用鼠标点击操作**：

| 点击目标 | 功能 |
|----------|------|
| 数值行左侧 `<` / 右侧 `>` | 调整 Workers 数量 / 验证轮数 / 文件大小上限 / 字符上限 |
| 「初始模型」的模型名 | 循环更换初始模型 |
| 岗位行（19 个岗位：4 流程 + 15 职能） | 第一次点 = 选中岗位；再点同一岗位 = 循环换模型 |
| `[+ 添加模型]` | **添加新模型**（五步流程） |
| `Esc` 或点击 ⚙ | 保存并关闭 |

**滚动**：面板内容（含快捷键列表）随滚轮 / `↑` `↓` 滚动，内容再多也不会溢出边框；内嵌滚动条显示位置。

### 添加模型（五步流程）

按 `a` 后依次输入，**每步按回车确认**：

```
步骤 1/5  供应商名称    如 deepseek / openai / ollama
步骤 2/5  Base URL      如 https://api.deepseek.com/v1
步骤 3/5  API Key       可留空跳过
步骤 4/5  模型 ID       如 deepseek-chat
步骤 5/5  显示名称      如 DeepSeek V3
```

添加完成后三键分支（界面中有提示）：

| 按键 | 行为 |
|------|------|
| `回车` | **继续添加同一供应商的模型**（只需再输模型 ID + 显示名称） |
| `空格` | **添加其他供应商的模型**（重新走五步） |
| `s` | **完成添加**，退出添加流程 |

自定义供应商默认走 OpenAI 兼容协议（`/chat/completions`）。

## 🛠️ 技术特点

- **零外部运行时依赖**：核心功能纯 Node.js 内置模块
- **SQLite 持久化**：Node 22+ 内置 `node:sqlite`，自动降级内存模式
- **多模型支持**：OpenAI / Anthropic / Ollama / Gemini
- **ANSI TUI**：纯控制台渲染，无需 ink 等重型依赖
