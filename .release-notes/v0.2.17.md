# ORcode v0.2.17 — 自然语言推理旁白

## 🧠 思考不再是标签，是有过程的推理

之前树里只显示「分析任务需求」「制定执行步骤」这种职责短语。现在**每个智能体**都产出完整的 5 步自然语言推理链，句子里带着真实任务摘要：

```
1. 🧠 接到「写一个游戏关卡的视觉方案」——我负责按方案写出可运行代码，先确认输入边界和要交付什么
2. ◎ 查看 现有文件、修改: 代码入口与调用链
3. 🧠 确认了：照方案直接写会漏掉边界输入，得先补一层校验
4. 🧠 所以决定：先写主流程再补边界处理，最后自查一遍再交出
5. ✓ 完成 — 本岗结论已产出，交给下游继续
```

- **覆盖范围**：19 个岗位（4 流程岗 + 15 职能岗）、HOR-loop 的每个阶段、以及**单模型普通对话**
- **岗位专属视角**：美术指导看视觉风格/配色、安全审计查越权路径、批评家找跳步论证、图像分析师核对图文不符……每个岗位的 `◎ 查看` 和「确认了」都不一样
- **逐条实时上屏**：推理句子一条条冒出来（子智能体并行时各岗独立推进），同时归档进该岗的只读子会话窗口
- **三类图标区分**：`◎` 查看/工具动作（蓝）、`🧠` 推理判断（黄）、`✓` 结论（绿）

## 🛠 实现

- `REASONING_PROFILES`：19 岗各一套 `role / check / finding / decide`
- `buildReasoning(key, instruction)`：拼出 5 步句子，插入真实任务摘要
- `emitReasoning`：同时写 `thought` 与 `subLog`
- `addThought` 上限 **3 → 12**，完整推理链不再被挤掉
- 子会话窗口「深度思考」块加行数保护，长推理不压到底部
- 树内思考行 / 窗口思考行都按 `◎`/`✓`/其他分色
